# Database — implementation notes

Решения, принятые при реализации [DATABASE.md](../DATABASE.md) в
`apps/api/prisma/schema.prisma`. Если решение меняется — обновить этот файл.

## Принятые бизнес-правила

| Вопрос | Решение |
|---|---|
| Гостевой заказ | **Не поддерживается.** Заказ оформляет только авторизованный пользователь (`Order.userId` обязателен). Гость может смотреть каталог и собирать корзину в браузере; при входе корзина переносится в `Cart`. |
| Момент списания остатков | **При создании заказа**, в одной транзакции с созданием `Order`. Только для товаров с `trackInventory = true`. |
| Возврат остатков | **При отмене заказа** (`CANCELLED`) — возвращается ровно то, что было списано по этому заказу (по записям `StockMovement` с `referenceId = order.id`). |
| Авторизация | Короткий access-token + refresh-token в httpOnly cookie. В `Session` хранится только хеш refresh-токена. |

## Остатки (DATABASE.md §7, §18)

- `Product.stockQuantity` — текущий остаток, `CHECK (stock_quantity >= 0)`.
- `StockMovement.quantity` — **знаковая** дельта: `IN`/`RETURN` > 0, `OUT` < 0,
  `ADJUSTMENT` ≠ 0 (проверяется `CHECK`).
- Любое изменение остатка = обновление `Product.stockQuantity` + запись
  `StockMovement` в одной транзакции.
- Защита от одновременных заказов: атомарное условное списание
  `UPDATE products SET stock_quantity = stock_quantity - $n WHERE id = $id AND stock_quantity >= $n`;
  если обновлено 0 строк — товара недостаточно, транзакция откатывается.
  `CHECK` в БД дополнительно гарантирует, что остаток не уйдёт в минус.

## Деньги

- Все суммы — `Int` в **тыйынах** (1 сом = 100 тыйын), рядом `currency` (`KGS`).
- `CHECK (... >= 0)` на всех суммах.

## Языки

- Поддерживаются `ky` (основной язык, по умолчанию) и `ru`. Поля `locale` — строка с `CHECK (locale IN ('ru','ky'))`.
- `User.locale` — выбранный язык интерфейса; `Order.locale` и `Notification.locale` —
  язык, на котором создан заказ / написано уведомление.

## Удаление данных

- Soft delete (`deletedAt`): `User`, `Product`, `Category`.
- Заказы, позиции заказов, история статусов, платежи и события платежей
  физически не удаляются: связи с ними `onDelete: Restrict`.
- `OrderItem` хранит snapshot (название, SKU, цена). Если товар всё же удалён
  физически, `OrderItem.productId` становится `NULL`, история сохраняется.
- `Order` хранит snapshot контактов покупателя и точки самовывоза
  (`pickupLocationName`, `pickupLocationAddress`).
- Уникальные `slug` / `sku` остаются занятыми после soft delete.

## Ограничения вне Prisma

Prisma не умеет описывать `CHECK` и частичные индексы, поэтому они добавлены
вручную в конец `prisma/migrations/*_init/migration.sql`:

- `locale IN ('ru','ky')` для всех таблиц с `locale`;
- `users.email = lower(email)` — email хранится в нижнем регистре;
- суммы и цены `>= 0`, `stock_quantity >= 0`;
- знак `stock_movements.quantity` по типу движения;
- `cart_items.quantity > 0`, `order_items.quantity > 0`, `product_units.quantity_value > 0`;
- `reviews.rating BETWEEN 1 AND 5`;
- категория не может быть родителем самой себя;
- `banners.starts_at < ends_at`;
- не более одного `is_primary` изображения на товар (частичный уникальный индекс).

## Отклонения от DATABASE.md и дополнения

| Что | Почему |
|---|---|
| `Order.orderNumber` — `Int` autoincrement | Уникальный, без коллизий, удобен для покупателя. Формат отображения (например `NE-000123`) — на frontend. |
| `Order.payments` — `Payment[]` | DATABASE.md §12: несколько попыток оплаты на заказ. |
| `Review.orderItemId` обязателен и уникален | Отзыв только после покупки, один на позицию заказа. Nullable-поле в составном unique не защищало бы от дублей (NULL ≠ NULL в PostgreSQL). |
| `User.phone` — индекс, не unique | DATABASE.md §17 требует уникальность только для email. |
| `User.locale` | ТЗ §11, §15: сохранение выбранного языка, язык уведомлений. |
| `Order.locale`, `pickupLocationName`, `pickupLocationAddress` | Snapshot для истории и уведомлений (DATABASE.md §11). |
| `Notification.locale`, FK `relatedOrderId → orders` | Уведомления на KG/RU; целостность связи. |
| `ProductTranslation.characteristics` (JSON `[{name, value}]`) | ТЗ §6.4 «Характеристики» — в DATABASE.md поля не было. |
| `ProductImage.storageKey`, `mimeType`, `sizeBytes`, `width`, `height` | Метаданные файла в S3 (ТЗ §18). |
| `Session.userAgent`, `ipAddress` | Для списка активных сессий; токен хранится только хешем. |
| `Banner`, `SiteContent` (+ переводы) | ТЗ §14 «Управление контентом» — в DATABASE.md моделей не было. |
| `PaymentEvent.payload`, `AuditLog.metadata` — `Json` | Вместо текста. |
| `PickupLocation.sortOrder` | Порядок вывода точек. |
| `Payment @@unique([provider, providerPaymentId])` | Один платёж провайдера не может быть записан дважды. |

## Seed

`pnpm db:seed` — идемпотентный. Создаёт:

- 5 категорий (RU из ТЗ; **KY-названия нужно проверить редактору**);
- 12 товаров из прайса ТЗ §6.2 с ценами в тыйынах; названия как в прайсе
  на обоих языках; описания, состав, вес, условия хранения **не заполнены**;
  остатки не известны → `trackInventory = false`, `stockQuantity = 0`;
- «Керемет шыпаа» без категории — тип продукта не известен;
- одну точку самовывоза, помеченную `[DEMO]`;
- демо-админа и демо-покупателя (пароли из `SEED_*_PASSWORD` или случайные,
  выводятся один раз);
- 3 демо-заказа (COMPLETED, CANCELLED, PENDING) с историей статусов, без платежей.

## Открытые вопросы к компании (влияют на данные)

- Состав, характеристики, вес/объём, единицы продажи, условия хранения
  (подтверждено: Нават 0.5 / 0.6 / 0.7 — литры).
- Тип и категория «Керемет шыпаа» (компания пока не уверена); подтверждение категорий остальных товаров.
- Названия и цены товаров, которые есть в Instagram, но нет в прайсе (компот, напитки в белых и
  тёмных бутылках) — будут добавлены после получения данных.
- Адрес, координаты, телефон, график точки самовывоза.
- Текущие остатки и кто их ведёт.
- Есть ли слоты времени самовывоза (поле `pickupTime` уже есть).
- Нужен ли перевод названия / адреса точки самовывоза на кыргызский.
- В профиле указаны доставка («жеткирүү») и оптовые продажи (отдельная форма на Tilda).
  По ТЗ на первом этапе только самовывоз и розница: нужно ли добавлять доставку и опт на сайт?
- Оригинал логотипа (SVG/PNG) — сейчас на сайте временный текстовый логотип.
- Беш бармак в прайсе — это фасованная лапша «Улуттук бешбармак»? (влияет на категорию и описание)

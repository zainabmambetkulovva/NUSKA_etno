# NUSKA_etno — Technical Specification

**Версия:** 1.0  
**Тип проекта:** Premium E-commerce  
**Направление:** Интернет-магазин натуральных и традиционных кыргызских продуктов  
**География:** Кыргызстан  
**Основные языки:** Кыргызский и русский  
**Архитектура:** Monorepo  
**Статус:** Разработка с нуля

---

# 1. Общая концепция проекта

NUSKA_etno — современный интернет-магазин, специализирующийся на продаже натуральных продуктов и традиционных кыргызских продуктов питания.

Главная идея проекта — объединить кыргызское национальное наследие, традиции, натуральность продуктов и современные технологии электронной коммерции.

Сайт должен создавать ощущение доверия, качества, уюта и связи с кыргызской культурой.

Это не обычный продуктовый магазин, а премиальный цифровой бренд с уникальным визуальным стилем, интерактивными элементами и современной 3D-графикой.

## Основные цели

- Создать современный интернет-магазин.
- Представить ассортимент компании.
- Обеспечить удобную покупку продуктов онлайн.
- Реализовать систему авторизации.
- Создать личный кабинет покупателя.
- Реализовать корзину и оформление заказов.
- Реализовать систему самовывоза.
- Создать полноценную административную панель.
- Обеспечить управление товарами, категориями и заказами.
- Реализовать мультиязычность.
- Создать уникальный интерфейс с 3D-сценами и анимациями.

# 7. 3D-система и анимации

3D и анимации являются одной из основных особенностей NUSKA_etno.

Необходимо создать не просто декоративные эффекты, а полноценную визуальную систему, которая работает на имидж бренда и улучшает пользовательский опыт.

## 7.1. Главная 3D-сцена

Главный визуальный объект — кыргызский дасторкон.

В сцене должны присутствовать:
- Традиционная посуда.
- Натуральные продукты.
- Кымыз.
- Мёд.
- Нават.
- Сары май.
- Традиционные элементы декора.

Требования:
- Реалистичные материалы.
- Мягкое освещение.
- Естественные тени.
- Объём и глубина.
- Оптимизированные 3D-модели.
- Плавная реакция на движение курсора.

## 7.2. Интерактивность 3D-сцены

Реализовать:
- Лёгкий поворот композиции при движении мыши.
- Плавное появление элементов.
- Небольшие анимации отдельных объектов.
- Плавное движение камеры.
- Переходы между состояниями сцены.

Не использовать чрезмерное вращение и резкие движения.

## 7.3. Анимированные орнаменты

Создать отдельную систему декоративных SVG-орнаментов.

Анимации:
- Плавное прорисовывание линий.
- Появление при прокрутке.
- Лёгкое движение декоративных элементов.
- Использование в переходах между секциями.

## 7.4. 3D-карточки продуктов

При наведении:
- Небольшой наклон карточки.
- Эффект глубины.
- Мягкое увеличение изображения.
- Плавное изменение тени.

## 7.5. Анимация корзины

При добавлении товара:
- Анимированное перемещение визуального элемента к иконке корзины, если это реализуемо без ухудшения производительности.
- Обновление количества товаров.
- Плавное подтверждение добавления.

## 7.6. Дополнительные анимации

- Плавное появление секций.
- Scroll animations.
- Parallax.
- Анимация логотипа.
- Hover effects.
- Page transitions.
- Loading screen с национальным орнаментом.

## 7.7. Производительность 3D

Обязательные требования:
- Lazy loading 3D-сцен.
- Оптимизация GLB/GLTF-моделей.
- Сжатие текстур.
- Ограничение частоты рендеринга там, где возможно.
- Отключение ненужных анимаций вне видимой области.
- Облегчённая версия для мобильных устройств.
- Поддержка prefers-reduced-motion.
- Fallback, если WebGL недоступен.

3D не должен мешать загрузке каталога и оформлению заказа.

# 12. Система заказов

Статусы:
- PENDING.
- CONFIRMED.
- PREPARING.
- READY_FOR_PICKUP.
- COMPLETED.
- CANCELLED.

Пользователь должен видеть актуальный статус заказа.

Администратор может изменять статус в соответствии с разрешёнными переходами.

Все изменения статусов необходимо сохранять в истории.

Архитектура должна предусматривать подключение платёжного провайдера.

Пока платёжный провайдер не определён:

- Предусмотреть разные способы оплаты.
- Подготовить обработку статусов платежей.
- Не имитировать успешную онлайн-оплату.

Возможность оплаты при получении должна быть согласована с компанией.

# 18. База данных

Использовать Neon PostgreSQL + Prisma ORM.

Предусмотреть модели:
- User.
- Session.
- Product.
- ProductTranslation.
- Category.
- CategoryTranslation.
- ProductCategory.
- ProductImage.
- Cart.
- CartItem.
- Favorite.
- Order.
- OrderItem.
- OrderStatusHistory.
- Payment.
- PaymentEvent.
- PickupLocation.
- Notification.
- Review.
- AuditLog.

Конкретную Prisma Schema необходимо спроектировать с учётом реальных связей и требований целостности данных.

Для товаров использовать единую модель Product с типом продукта, чтобы в будущем можно было расширять ассортимент.

Предусмотреть:
- UUID.
- createdAt.
- updatedAt.
- deletedAt для подходящих сущностей.
- Уникальные ограничения.
- Индексы.
- Foreign keys.
- Транзакции для критичных операций.

Цены хранить в целых денежных единицах (сомах или тыйын) с явным указанием валюты.

Изображения хранить в S3-compatible Storage, а в PostgreSQL сохранять ссылки и метаданные.

# 25. Правила разработки

1. Не создавать фиктивные функции.
2. Не оставлять основные функции в виде TODO.
3. Не использовать статические данные вместо реального Backend там, где требуется работа с БД.
4. Не дублировать компоненты и бизнес-логику.
5. Не усложнять архитектуру без необходимости.
6. Соблюдать TypeScript.
7. Сохранять чистую архитектуру.
8. Использовать единые правила форматирования.
9. Обеспечить безопасность.
10. Все критичные операции проверять на Backend.
11. Оптимизировать 3D и анимации.
12. Не допускать, чтобы декоративные эффекты ухудшали работу магазина.
